# プレイログ（匿名のプレイ記録）と分析

どの機能がよく使われ、どれが使われていないか。基礎能力を上げる理由が働いているか。スキルツリーはどう伸ばされているか。仕入れルートは偏っていないか。どんなプレイスタイルがあるか。序盤のどこで遊ぶのをやめているか。これらを、実際のプレイヤーの記録から見るための仕組み。

## しくみ

```
ゲーム（ブラウザ）            サーバー（Vercel）                 手元
engine/telemetry.js ─記録点─┐
ui/telemetry.js  ─送信（束）─→ /api/telemetry ─→ Upstash Redis ─→ tools/analytics/fetch.mjs ─→ report.mjs ─→ dist/analytics.html
                               （日ごとのリスト・180日で消える）     （TELEMETRY_READ_TOKEN）
```

| ファイル | 役目 |
| --- | --- |
| `src/engine/telemetry.js` | 記録点（何も import しない）。送り先がつながっていなければ何もしない |
| `src/engine/playlog.js` | 月末の様子・ゲームの条件・エンディングを短い形にする（ブラウザとボットで共通） |
| `src/ui/telemetry.js` | ブラウザ側：匿名ID・送信の待ち行列（localStorage）・送信・設定のON/OFF |
| `api/telemetry.js` / `api/_telemetry.js` | 受け取り（形と大きさの確認・回数制限・保存）と読み出し（トークンつき） |
| `tools/analytics/lib.mjs` | 集計（プレイごとにまとめて、各分析の数字にする） |
| `tools/analytics/report.mjs` | 分析レポート（HTML）を作る |
| `tools/analytics/fetch.mjs` | 本番の記録を日ごとに取ってくる |
| `tools/analytics/simulate.mjs` | ボットに遊ばせて模擬データを作る（レポートの確認用） |

## 記録するもの

1つの出来事は `{ g: プレイID, at: 時刻（秒）, e: 種類, w: 週, ... }`。ブラウザは40件ごと・1分ごと・アプリを切り替えたとき・エンディングで、まとめて送る（`{ v:1, pid: 端末の匿名ID, sid: セッションID, dev: 'm-web' など, lang, ev:[…] }`）。

| 種類 | いつ | 中身 |
| --- | --- | --- |
| `new` / `sess` | ゲームを始めた／再開した | 難易度・キャリアの型・チャレンジ・引き継ぎ・師匠 |
| `unl` | 行動・夜の行動・右のボタンやメニューが初めて使えるようになった週 | `ids`（`store`、`night:online`、`ui:market` など） |
| `cmd` | 行動を実行した | 行動のID、夜なら `n:1`、ルーティン・おまかせなら `auto:1`。夜に寝たら `sleep` |
| `ui` | 画面を開いた | モーダルの見出し、右のボタン（`tab:inv` など）、メニューの項目（`menu:market` など） |
| `ab` | 基礎能力を上げた | `how`（`manual`：+1/+5、`auto`：自動で割り振る）と上げた量 |
| `cv` | 経験点を振り替えた | どこから・どこへ・量 |
| `sk` / `cure` | スキルツリーのパネルを取った／不調を治した | パネルのID、無料でもらったら `free:1` |
| `tut` / `quest` / `stage` | チュートリアルの目標・ミッションを達成した／ステージが上がった | 番号・ID |
| `repay` / `routine` | 繰上げ返済した／ルーティンを始めた | 金額／行動と週数 |
| `mon` | 月末 | その月の集計 `t`（`buy`：「行動:仕入れ先」ごとの個数と金額、`sell` と `prof`：販路ごとの売上と利益、`pay`：現金かカードか）と、月末の様子（所持金・借金・純資産・ステージ・基礎能力5つ・使っていない経験点5種・パネルの数・ルートごとのパネル数・体力・やる気・TOKU・評価・在庫） |
| `end` | エンディング | ENDのID・ランク・純資産・称号・ステージ |

送らないもの：名前（ランキングの登録名も）、ランキングのプレイヤーID、端末の詳しい情報。サーバーはIPアドレスを回数制限にだけ使い、保存しない。

### 止め方・既定

- メニュー →「設定」→「データ」の **プレイ記録を送って改善に協力する** でON/OFF。OFFにすると、送っていない分も消す
- 既定はON。ただし `localhost`・LANのアドレス・`https` でないページ・自動操作のブラウザ（`navigator.webdriver`）では、設定でONにしない限り送らない（開発中の記録が混ざらないように）

## 公開のための設定（人の作業）

保存先はオンラインランキングと同じ Upstash Redis（`docs/13_online_ranking.md`）。追加で：

1. Vercel の環境変数に **`TELEMETRY_READ_TOKEN`**（長いランダムな文字列）を入れて、再デプロイする。読み出しに使う
2. 手元で `TELEMETRY_READ_TOKEN=... npm run analytics:fetch -- 2026-10-01 2026-10-31` を実行すると、`analytics-data/日付.jsonl` に保存される（リポジトリには入れない）
3. `npm run analytics:report` で `dist/analytics.html` ができる（`analytics-data/` の全ファイルを読む。ファイルを指定してもよい）

容量の目安：1プレイを10年遊ぶと約500件・40KB前後。Upstash の無料枠（256MB）なら数千プレイぶんは十分入る。1つのIPから1時間に240回まで、1回64KB・400件まで。

## 分析レポートの見方

`npm run analytics:sim -- 40` で模擬データ（ボット40プレイ。途中でやめる人をまねて週数を打ち切る）を作り、`npm run analytics:report -- analytics-data/sim.jsonl` で形を確かめられる。ボットは画面を開かないので、画面・メニューの欄は空になる。

| 知りたいこと | レポートの章 | 数字の決め方 |
| --- | --- | --- |
| どの機能がよく使われているか／使われていないか | 機能の利用率 | 使えるようになってから8週以上遊んだプレイ（または使ったプレイ）を分母に、1回でも使ったプレイの割合。20%未満を「使われていない機能の候補」として上に出す。行動の内訳（全行動に占める割合）、開かれた画面の上位も |
| 基礎能力を上げるインセンティブ | 基礎能力を上げるインセンティブ | 能力強化が使えるプレイのうち上げた割合（手で／自動で）、初めて上げるまでの週、各年の終わりの能力と「使っていない経験点」の中央値、能力の合計と純資産の順位相関（+1に近いほど上げた人が稼げている。0付近なら上げる理由が弱い。貯めこんだ経験点と純資産がプラスの関係なら、経験点を使わずに稼げてしまっている） |
| スキルツリーの強化傾向 | スキルツリーの強化傾向 | 24週以上遊んだプレイで、経験点で取ったパネルのルート、最初に伸ばしたルート（最初の3枚）、いちばん伸ばしたルート、パネルごとの取得率と取った週の中央値、一度も取られていないパネル |
| 仕入れルートの偏り | 仕入れルートの偏り | 仕入れ額の行動ごとの割合（年ごとの内訳つき）、1プレイでいちばん使うルートが仕入れ額の何割か（分布と中央値）、5%以上使うルートの数、販路ごとの売上と利益率、カード払いの割合 |
| プレイスタイルの大別 | プレイスタイルの大別 | 1年以上遊んだプレイを、行動の内訳・販路の売上の割合・ルートごとのパネルの割合・TOKUの低さで標準化し、k-means（k=2〜6、シルエット係数で決める）。各グループの特徴（全体より高い項目）・行動の内訳・純資産・多いEND |
| 序盤の離脱ポイント | 序盤の離脱ポイント | どこまで遊んだか（週）とチュートリアルの漏斗、離脱したプレイの最後の週、離脱する直前にしていたこと、チュートリアルのどこで離れたか、セッション数。離脱は「エンディングまで行かず、データの最後から3日以上記録がない」（`--idle 7` などで変えられる） |

## 注意

- 記録を始める前からのセーブで遊んでいる人は、`new` がなく `sess` から始まる。離脱の漏斗には `new` のあるプレイだけを使う
- 同じ端末で何度も遊ぶとプレイ（`g`）は分かれるが、端末ID（`pid`）は同じ。ブラウザのデータを消すと別の人として数えられる
- 1か月以上データを溜めてから見る。プレイ数が少ないうちは、プレイスタイルの分け方や相関は大きく揺れる
